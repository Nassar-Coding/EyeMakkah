# EyeMakkah — Visual Design System

## Product feeling

Community-first, contemporary Saudi consumer product, editorial rather than dashboard-like.

Core metaphor:

**Makkah itself is alive inside the phone.**

## Composition rules

Prefer:
- edge-to-edge photography
- image + text editorial rows
- whitespace and thin dividers
- timeline treatment for Plan
- feed/post treatment for community content
- practical information as facts, not cards
- trust information inline
- occasional asymmetry

Avoid:
- every section in a rounded card
- six-card consultancy grids
- excessive green
- glowing AI visual language
- government/institutional visual language
- chip overload
- generic icon grids
- huge radii on every rectangle
- heavy shadows

## Radius

- controls: ~8px
- normal containers: ~11–14px
- large media: ~14–20px
- 999px only for actual pills, filters and status chips

## Shadows

Almost none. Reserve for overlays, sheets, floating elements and reviewer shell.

## Iconography

Use one coherent icon family. Do not make every concept an icon. Icons support navigation/actions rather than replacing rich content.

## Photography

Photo-led hierarchy:

people → place → food → event/activity → community → practical facts

Use real Makkah photography or truthful contextual images whenever possible. Do not imply a generic image is a specific named restaurant or current event.

## Typography

- intended: 29LT Zarid Sans if properly licensed
- prototype fallback: Tajawal or Noto Kufi Arabic
- no proprietary font files in deliverables
